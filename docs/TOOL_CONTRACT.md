# Tool Contract

The standalone impact source handoff preserves the first direct consumer's exact declaration-range read when it is an admitted callable (function, method or constructor) already in another file and the proposed route omits it. File-only hints and navigation/excerpt recoveries retain their existing handoff behavior. A route may replace that prefix only when it identifies the same selected direct node and physical generation and covers its complete bounded read in the same file/project; partial or gapped coverage is insufficient. Same-file direct bridges retain the existing cross-file route preference. Previously allocated routes, actions, witnesses and walk counts/gaps stay intact under the existing response/footer budgets. Later optional spare-space caller samples may be smaller because the restored prefix consumes bytes; omission counts still reflect the displayed sample.

Standalone compact impact and Blast summaries retain their original four preferred direct consumers and every previously allocated route, source action, frontier and count. Only after the final display and source handoff are fixed, spare bytes may append full selected direct-consumer rows in retained graph order, up to eight total and within the existing2KiB per-row/12KiB response bounds, reserving256 bytes for freshness. An oversized row is skipped without hiding later rows that fit. Added rows retain exact witnesses and literal recovery actions; the omitted count decreases accordingly. If no row fits, the original output and limit explanation remain byte-identical. Graph output and typed edit-safety assessments are unchanged; a larger sample is not exhaustive or runtime proof.

VB invocation names do not use the global source-property name fallback when semantic resolution is incomplete. Ordinary unresolved call text and positions remain available. Resolved source properties and unique expression-scoped source-property candidates remain eligible; candidate inspection stops after sixteen entries, and mixed, non-property or ambiguous candidates remain unresolved. For non-invocation syntax, including implicit calls and `With` members, a known receiver symbol or candidate prevents borrowing a global property when the member has no positive property evidence, even if the receiver's type is unresolved. An implicitly declared `For Each` local whose type is unavailable can recover a unique source property from its exact collection's semantic array element type; the control-variable symbol must match, and at most sixteen enclosing loops are inspected. Direct assignment-target members retain the existing lexical write fallback; members nested in an assignment receiver or index argument do not gain that exception. Genuinely unbound receivers retain the existing lexical fallback. These are static source observations, not runtime binding guarantees. Stored graph corrections require ordinary VB re-extraction under the updated parser identity.

Ordinary VB invocations resolved by the compiler to an admitted source method retain an exact declaration locator: project-relative path, semantic member ID, declaration line, UTF-16 span and syntax-source SHA-256. Ingestion validates it against the current cohort or selected inherited target, then stores bounded managed evidence tied to both endpoint generations, physical file hashes and parser provenance. CodeMap callable recovery and revision-admitted incoming impact revalidate this evidence on every read; stale or malformed evidence is an explicit `source_call_binding_unverified` gap, never a name/arity choice between overloads. Known-source calls whose locator is unavailable stay unresolved and cannot enter generic placeholder resolution. Interface dispatch remains a separate route; external and unbound invocations retain their existing semantics. This is a compiler-selected static declaration, not proof of runtime dispatch. Native parser contract `vb-ingestion-parser-v6` forces ordinary re-extraction before the new evidence is available. Native output allows at most256 source locators per file and marks further calls unknown; ingestion admits at most262144 marked calls/128MiB estimated evidence per publication with actual-sized memory reservation, bounded inherited reads and fail-closed publication on overflow. Managed edge evidence retains at most16 proofs and32 positions per proof, disclosing truncation.

`get_full_method_body` accepts `file_path` plus `source_ranges: [{line_start, line_end}, ...]` for one to three ordered, nonoverlapping inclusive windows in one permitted file.
