# Tool Contract

Impact and Blast Radius can offer `type_name_inspection` for a selected canonical class, including classes with zero observed graph dependents. Its lazy `grep_project` action searches the final dot-separated type name literally and case-insensitively within the target directory, with eight results and indexed freshness `off`. This can recover constructor, return-type or field mentions without adding graph dependencies. Execute returned current-source actions before inferring a producer or serialization route. Comments, prefix names and unrelated types can match; aliases and other directories remain unassessed. The action is optional within the existing graph/summary byte caps and cannot displace existing evidence; `type_name_inspection_omitted=true` reports clipping when space permits. Unsupported names, root-level files and unadmitted targets have no such action.

`grep_project` with `regex=true` uses Rust regex syntax. Invalid patterns, including unsupported look-around or backreferences, return an invalid-parameters error before searching, even for an empty scope or indexed-only freshness mode. They never become successful zero-match results. Correct the pattern or explicitly use `regex=false` for literal text; a valid search with no matches remains successful.

CodeMap `symbol_name` lookup includes selected native `class` records alongside function, method, constructor and property records. This makes named data contracts navigable even when their filenames do not match their type names. Some extractors represent interfaces as `class`; the reported kind is indexed provenance, not language-level type binding. Exact-file bare-name recovery also covers qualified class names. Exact names still take priority over terminal-name alternatives, and distinct matching identities remain candidates. Class results offer source-range and impact actions, without a method-edit-context action. The same 64-key, 2MiB decode, eight-candidate and 500ms observation budgets apply; a directory page attempts at most eight files and 40 prefix seeks. Ordinary declaration inventory and extraction are unchanged. Other kinds and unobserved records remain unknown.

A directory `symbol_name` page with zero observed candidates can offer `name_search_recovery`: a lazy, literal `grep_project` search for the final dot-separated name segment. It preserves the requested directory boundary and exclusions, searches indexed `memory` with eight results, and does not alter graph candidates or pagination. Matches are text leads, including possible comments or unrelated names; execute their current-source recovery before relying on them. When `path_contains` is present, recovery is explicitly omitted because grep cannot preserve that filter. This is not a declaration, reference, binding or absence guarantee.

Impact summaries can include `hinted_file_declarations`: at most two selected declaration leads, one per displayed `source_routes.file_hints` file. These reuse explicit current-source range actions from the held graph when a declaration is not already shown as an immediate consumer or source-route node. They can help inspect a consumer across an API/file boundary without representing a callable-only route or proving value flow or runtime binding. Only positive indexed spans of at most120 lines with matching range actions qualify; method bounds and current indexed freshness remain unverified. Observed/omitted counts cover eligible retained declarations in the hinted files, not the project. This optional block uses spare space after existing evidence and capped-member recovery, before consumer-expansion shortcuts; standalone and nested summaries keep their12KiB bounds.

Impact and Blast Radius may expose `terminal_member_inspection` for an admitted TypeScript function. Its first lazy `grep_project` action searches literal `.member` in the target directory, so bare declarations, local names and prose do not fill the result cap first. `unrestricted_fallback` searches the bare name in the same directory for spaced/bracket access and other mentions. Both use indexed freshness `off`, eight matches and returned current-source recovery actions; neither binds a receiver, adds callers or proves absence. Comments, strings and prefix names can still match. Under response pressure the broad fallback is omitted before the focused action, with `unrestricted_fallback_omitted=true`; existing graph evidence and response caps take priority. When a capped unresolved-member scan observes no callers and the initial summary omits this search, the final envelope can use remaining space to restore it before optional consumer-navigation shortcuts. This preserves already selected facts, witnesses and source routes, remains within12KiB, and does not increase scan work or establish absence when recovery still cannot fit.

## Current source reads

`get_full_method_body` accepts `file_path` plus `source_ranges: [{line_start, line_end}, ...]` for one to three ordered, nonoverlapping inclusive windows in one permitted file. ## ADP Infrastructure (Phase 27)

The `autonomous_decision_gate` tool is backed by production hardening infrastructure:

### Rollout Policy Engine
ADP verdicts pass through `apply_rollout_policy()` which applies phase-specific behavior:
- **Shadow**: Log verdict, always return Allow (no enforcement)
- **Advisory**: Log verdict, return Allow but include warning annotation
- **Guarded**: Enforce verdict — Allow, Deny, Abstain applied as-is
- **Autonomous**: Enforce verdict — identical to Guarded (full autonomous operation)
- **Kill-switch override**: When `adp_kill_switch=true`, ALL verdicts forced to Deny regardless of rollout phase

Config fields: `adp_rollout_phase` (default: `"shadow"`), `adp_kill_switch` (default: `false`)

### Deterministic Replay
- `replay_from_scenario(scenario)` — converts serialized `AdpScenarioInput` into `AdpInput` for reproducible verdict computation
- `run_corpus(corpus)` — batch-runs a labeled corpus and produces `AdpConfusionMatrix` with false-allow/false-deny rates

### JSON Decision Reports
- `build_decision_report(input, decision)` — generates `AdpDecisionReport` with:
  - Per-gate `GateEvidence` (gate_id, passed, score, detail)
  - `ConfigSnapshot` (rollout_phase, kill_switch, min_extraction_confidence, max_blast_radius)
  - Full `AdpScenarioInput` for replay
  - ISO 8601 timestamps, verdict, failed gate IDs

### Runtime Evidence Schemas
- `RuntimeEvent` — typed event: `ControlInteraction`, `Route`, `SqlExecution`, `StateMutation`
- `RuntimeEvidenceBatch` — collection of events with `validate_batch()` schema validation
- `ReconciliationResult` — per-path reconciliation with `Confirmed`/`Contradicted`/`Unmatched` statuses
